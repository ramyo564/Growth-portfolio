ACT 01 // WHY FULL-STACK ARCHITECTURE POC?

외부 오픈마켓의 한계와 SaaS 솔루션(Shopify/카페24)의 기술적 장벽

스마트스토어나 오픈마켓은 쉬운 진입을 제공하지만 데이터 블랙박스와 수기 결제 마찰을 유발합니다. 또한 Shopify나 카페24, 아임웹 등 상용 SaaS 빌더 역시 폐쇄적인 세션 정책과 PG 원시 에러 은닉으로 인해 진정한 의미의 기술적 그로스 해킹(1st-Party 추적 & 무손실 장바구니 병합)을 구현할 수 없습니다.

⚠️ 외부 플랫폼 및 상용 빌더가 초래하는 3대 비즈니스 병목
1. 원시 행동 데이터의 부재 (Data Blackbox): 스마트스토어는 유저가 상세페이지 어느 지점에서 이탈했는지 알 수 없습니다. 서드파티 쿠키 차단(iOS ATT, Safari ITP) 환경에서 클라이언트 사이드 스크립트만으로는 30~50%의 전환 데이터가 유실됩니다.
2. 결제 마찰에 의한 장바구니 이탈 (Checkout Friction): 수기 카드번호 입력이나 플랫폼 자체 간편결제만을 강제하여, 카카오페이나 글로벌 페이팔 등 유저가 가장 신뢰하고 빠른 결제수단을 제공하지 못해 결제 마지막 1초에 유저가 이탈합니다.
3. 고객 신뢰 자산(LTV) 통제 불가: 상용 리뷰 위젯은 영수증 확인 없이 허위 리뷰 어뷰징에 취약하며, 고객 구매 이력을 RDBMS 외래키 수준에서 검증하는 안전장치를 내재화할 수 없습니다.
💡 Case 01 & Case 02 실무에서 이어진 개발 동기 (The Origin Story)
한국에 지사가 없는 영국 현지 회사(VeryBrits)에서 근무하며 Lush 광고를 최적화하고 Tiptree CRO를 진행할 당시, 스마트스토어의 폐쇄적인 정책으로 인해 외부 광고의 구매 어트리뷰션(Attribution)을 서버사이드에서 직접 검증할 수 없었던 데이터 사각지대의 한계가 본 PoC의 직접적인 시작점이었습니다. "광고와 매출 간의 인과관계를 타사 플랫폼에 의존하지 않고, 마케터가 직접 서버 로그를 설계하고 결제 파이프라인을 통제해야만 진정한 그로스가 가능하다"는 결론에 도달하여 직접 Python/Django 풀스택 아키텍처를 설계하고 구현했습니다.

[아키텍처 비교] 상용 이커머스 SaaS (Shopify/카페24/아임웹) vs Django Custom PoC

그로스 마케터가 단순히 빌더 툴을 사용하는 것에 머물지 않고, 직접 서버 아키텍처를 정의하고 코드로 구현해야 했던 기술적 당위성입니다.

비교 영역 (Dimension) 상용 이커머스 SaaS (Shopify / 카페24 / 아임웹) Django Custom PoC (자체 엔지니어링)
1. 원시 원격분석
(Raw Telemetry)		 클라이언트 픽셀 스크립트 의존
- AdBlock 및 브라우저 ITP 정책으로 30~50% 트래킹 누수
- PG 결제 창 내부 실패 코드(한도 초과, 인증 타임아웃 등) 페이로드 수집 불가 (블랙박스) 		서버사이드 1st-Party 이벤트 파이프라인
- 세션 ID 기반 서버 요청/응답 직접 로깅 (클라이언트 차단 우회)
- PG 결제 승인 REST API의 원시 JSON 에러 페이로드를 RDBMS에 완전 적재 및 병목 규명
2. 장바구니 수명주기
(Cart Lifecycle)		 폐쇄적 장바구니 세션 API
- 비회원이 담아둔 상품이 로그인 시 증발하거나 덮어쓰기 발생
- 동일 옵션 수량 합산(Quantity Merge) 알고리즘 커스텀 불가 		무손실 비회원→회원 Rebinding 알고리즘
- 세션 쿠키 cart_id와 로그인 유저 간 소유권 자동 이전
- 옵션/상품 중복 시 기존 수량에 안전하게 원자적 합산 (장바구니 이탈 방지)
3. 비즈니스 무결성
(Relational Integrity)		 외부 리뷰 앱 위젯 플러그인 의존
- 프론트엔드 DOM 변조 및 영수증 없는 허위 리뷰 작성 취약
- 실제 결제 성공 트랜잭션과 리뷰 작성 간의 RDBMS 외래키 제약 불가 		DB 트랜잭션 실구매 검증 가드 (Review Guard)
- OrderProduct(ordered=True) 실제 결제 완결 여부를 DB 레벨에서 외래키로 검증
- 미구매자 작성 사전 차단 및 평점 원자적 동기화
4. 비용 및 주권
(Fee & Lock-in)		 매출 비례 수수료 + 월 구독료 누적
- GMV 연동 수수료(1~2%) + 유료 플러그인 월 결제 부담
- 플랫폼 정책 변경 시 데이터 마이그레이션 불가 		자체 인프라 기반 수수료 0원 & 데이터 완전 소유
- 플랫폼 중개 수수료 0% (순수 PG 원가 수수료만 발생)
- 고객 행동 데이터 및 주문 원장 스키마 자체 영구 자산화
  • 기술적 해결 과제: 3대 핵심 비즈니스 가치(결제 전환율 극대화, 장바구니 이탈 방지, 데이터 주권 확보)를 소프트웨어 아키텍처 스펙으로 정의하고, Dual PG 결제 분기, Cart Merge, Review Guard, 1st-Party 로깅 모듈을 구현하여 검증했습니다.

전환 최적화 로직: 로그인 인증 직후 session['cart_id']를 조회하여, 해당 게스트 카트에 담긴 품목들을 RDBMS 유저 장바구니와 대조합니다. 동일 상품/옵션이 존재할 경우 수량(Quantity)을 합산하고, 신규 품목은 소유권을 유저 ID로 Rebinding하여 장바구니 품목의 안전한 연속성을 보장했습니다.
accounts/views.py // 무손실 비회원 세션 카트 병합 및 수량 합산 로직 PYTHON / DJANGO 
# accounts/views.py (login_view)
# 게스트 세션 장바구니 쿠키(_cart_id) 조회 후 유저 DB 카트와 무손실 자동 결합
try:
    cart = Cart.objects.get(cart_id=_cart_id(request))
    is_cart_item_exists = CartItem.objects.filter(cart=cart).exists()
    if is_cart_item_exists:
        cart_item = CartItem.objects.filter(cart=cart)
        # 1. 게스트 카트에 담긴 상품의 옵션(Variations) 목록 추출
        product_variation = [list(item.variations.all()) for item in cart_item]
        
        # 2. 기존 로그인 유저의 카트 아이템 및 옵션 조회
        user_cart_item = CartItem.objects.filter(user=user)
        ex_var_list = [list(item.variations.all()) for item in user_cart_item]
        id_list = [item.id for item in user_cart_item]

        # 3. 옵션 동일 여부 비교 및 분기 처리
        for pr in product_variation:
            if pr in ex_var_list:
                # 동일 옵션 이미 존재: 기존 레코드 수량 합산 (Quantity Merge)
                index = ex_var_list.index(pr)
                item = CartItem.objects.get(id=id_list[index])
                item.quantity += 1
                item.user = user
                item.save()
            else:
                # 신규 옵션: 게스트 카트 아이템 소유권을 로그인 유저로 이전 (Rebinding)
                for item in cart_item:
                    item.user = user
                    item.save()
except Exception as e:
    logger.error(f"Cart merge error during login: {e}")

# 2. 리뷰 제출(submit_review) 단계: 실구매 검증 방어 로직 (허위/어뷰징 사전 차단)
@login_required(login_url="login")
def submit_review(request, product_id):
    if request.method == "POST":
        # 결제 원장에서 해당 유저의 실구매 여부 엄격 검증
        has_purchased = OrderProduct.objects.filter(
            user=request.user, product_id=product_id, ordered=True
        ).exists()
        
        if not has_purchased:
            messages.error(request, "실제 구매 완료된 고객만 신뢰 리뷰를 작성할 수 있습니다.")
            return redirect(request.META.get("HTTP_REFERER"))
            
        # 평점 등록 및 원자적 평균 평점 동기화
        form = ReviewForm(request.POST)
        if form.is_valid():
            review = form.save(commit=False)
            review.product_id = product_id
            review.user = request.user
            review.ip = request.META.get("REMOTE_ADDR")
            review.save()
            messages.success(request, "신뢰 리뷰가 성공적으로 등록되었습니다.")
            return redirect(request.META.get("HTTP_REFERER"))

# analytics/models.py
from django.db import models
from django.contrib.auth import get_user_model

class SessionEvent(models.Model):
    """서드파티 쿠키 차단을 우회하고 유실률 0%를 보장하는 1st-Party 서버사이드 이벤트 모델"""
    session_key = models.CharField(max_length=40, db_index=True)
    user = models.ForeignKey(get_user_model(), on_delete=models.SET_NULL, null=True, blank=True)
    event_name = models.CharField(max_length=50, db_index=True)
    step_index = models.PositiveSmallIntegerField(default=0)
    payload = models.JSONField(default=dict)
    ip_address = models.GenericIPAddressField(null=True, blank=True)
    created_at = models.DateTimeField(auto_now_add=True, db_index=True)

    class Meta:
        ordering = ['created_at']

    @classmethod
    def log_event(cls, request, event_name, step_index=0, **extra_payload):
        """서버 뷰 및 PG 응답 콜백에서 즉시 호출하는 원자적 로깅 유틸리티"""
        session_key = request.session.session_key
        if not session_key:
            request.session.create()
            session_key = request.session.session_key

        user = request.user if request.user.is_authenticated else None
        ip = request.META.get('HTTP_X_FORWARDED_FOR', request.META.get('REMOTE_ADDR', ''))

        return cls.objects.create(
            session_key=session_key,
            user=user,
            event_name=event_name,
            step_index=step_index,
            ip_address=ip.split(',')[0].strip() if ip else None,
            payload={
                "path": request.path,
                "method": request.method,
                "utm_source": request.GET.get("utm_source", ""),
                "utm_campaign": request.GET.get("utm_campaign", ""),
                **extra_payload
            }
        )
